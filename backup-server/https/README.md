# HTTPS для резервного сервера (для браузерной версии)

Браузер не пускает запрос со страницы `https://` на обычный `http://` сервер.
Чтобы резерв работал прямо из браузера, ему нужен защищённый адрес.

## Вариант 1. Готовый туннель — 1 клик (рекомендуется)

Ничего настраивать не нужно, сертификат выдаётся автоматически.

1. Запустите резервный сервер обычным способом (`run.bat` или `start.bat`).
2. В этой папке запустите **`tunnel.bat`**.
   Первый раз он скачает служебную программу (около 50 МБ, нужен интернет).
3. В окне появится строка вида:

```
https://mine-vent-backup.trycloudflare.com
```

4. Скопируйте её в админ-панель → **Сервер расчёта** →
   «Адрес аварийного сервера (URL)» → «Проверить связь» → «Сохранить».

Окно туннеля не закрывать — пока оно открыто, адрес работает.

**Важно:** при каждом перезапуске туннеля адрес меняется. Для постоянного
адреса нужен бесплатный аккаунт Cloudflare и привязка своего домена —
это вариант 2.

## Вариант 2. Постоянный адрес на своём домене

Если у предприятия есть домен (например `mine.ru`):

1. Зарегистрируйте бесплатный аккаунт на cloudflare.com и добавьте домен.
2. На резервном ПК выполните:

```
cloudflared.exe tunnel login
cloudflared.exe tunnel create pvs-backup
cloudflared.exe tunnel route dns pvs-backup calc.mine.ru
cloudflared.exe tunnel run --url http://127.0.0.1:8800 pvs-backup
```

3. В админ-панели укажите `https://calc.mine.ru/`.

Адрес больше не меняется, можно поставить в автозапуск.

## Вариант 3. Свой nginx внутри сети

Подходит, если наружу выходить нельзя и есть свой сертификат предприятия.
Файл `nginx.conf.example` в этой папке — готовый образец конфигурации.

## Что проще всего

Если резерв нужен только на аварийный случай — используйте **десктопную
версию** программы: там ограничение браузера не действует и обычный адрес
`http://IP:8800/` работает сразу, без всякого HTTPS.
