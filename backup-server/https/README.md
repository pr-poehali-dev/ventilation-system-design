# Доступ к резервному серверу из любой точки России

Резервный сервер на своём ПК по умолчанию доступен только внутри локальной
сети. Чтобы к нему могли подключаться инженеры откуда угодно, нужен внешний
адрес. Ниже способы — по убыванию надёжности.

---

## Вариант 1. Второй облачный сервер (самый надёжный)

Резервом может быть не ваш ПК, а **вторая копия расчёта в облаке на другом
аккаунте**. Тогда:

- адрес доступен из любой точки, всегда;
- не нужен ни туннель, ни проброс портов, ни дежурный ПК;
- ничего не сломается из-за политики сети предприятия.

Порядок: заведите второй проект/аккаунт с этой же программой, скопируйте
адрес его расчётной функции и вставьте в админ-панель как аварийный сервер.
Вычислительное время у аккаунтов считается раздельно — когда кончится на
основном, расчёты пойдут на втором.

Это тот сценарий, под который поле «Адрес аварийного сервера» задумано
изначально.

---

## Вариант 2. Проброс порта на роутере (постоянный адрес, без посредников)

Подходит, если у предприятия есть постоянный внешний IP-адрес.

1. Попросите системного администратора пробросить внешний порт (например
   8800) на внутренний адрес резервного ПК `192.168.0.179:8800`.
2. Узнайте внешний адрес: откройте на резервном ПК `https://2ip.ru`.
3. Запустите сервер в защищённом режиме: `https\secure.bat`.
4. В админ-панели укажите `https://ВНЕШНИЙ-АДРЕС:8800/`.
5. Каждое рабочее место один раз открывает этот адрес в браузере и принимает
   защиту («Дополнительно» → «Перейти на сайт»).

Если внешний адрес меняется, подключите бесплатный сервис динамических имён
(DDNS) на роутере — получите постоянное имя вида `mine.ddns.net`.

---

## Вариант 3. Туннель ngrok (работает через обычный порт 443)

Используйте, если `tunnel.bat` в вашей сети не подключается: Cloudflare
требует порт 7844, а он у вас закрыт (в окне видны ошибки
`HTTP/2 connection is blocked` и `i/o timeout`). ngrok работает через
стандартный порт 443, который открыт почти везде.

1. Зарегистрируйтесь бесплатно: https://dashboard.ngrok.com/signup
2. Скопируйте свой authtoken из личного кабинета.
3. Запустите `tunnel-ngrok.bat`, вставьте токен (запрашивается один раз).
4. В окне появится строка `Forwarding  https://xxxx.ngrok-free.app`
5. Этот адрес вставьте в админ-панель.

Адрес доступен из любой точки. При перезапуске меняется (на платном тарифе
можно закрепить постоянный).

---

## Вариант 4. Cloudflare-туннель (если сеть его пропускает)

`tunnel.bat` — запуск в один клик, регистрация не нужна.
Требует открытый исходящий порт 7844. Если в окне бесконечно повторяются
ошибки соединения — этот способ в вашей сети не работает, берите вариант 3.

---

## Вариант 5. Свой nginx с сертификатом предприятия

Для закрытого контура со своей инфраструктурой — образец `nginx.conf.example`.

---

## Что выбрать

| Ситуация | Способ |
|---|---|
| Нужен надёжный резерв для всех пользователей страны | Вариант 1 |
| Есть свой внешний IP и админ | Вариант 2 |
| Ничего нет, нужно быстро | Вариант 3 |
| Все инженеры в одной сети с сервером | Внешний адрес не нужен, хватит `secure.bat` |
