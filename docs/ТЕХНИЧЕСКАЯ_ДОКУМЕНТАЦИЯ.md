## 1. ОБЩИЕ СВЕДЕНИЯ О ПРОГРАММЕ

**Полное наименование:** Программа для электронных вычислительных машин «ПВ-Система» (Проектирование Вентиляции — Система).

**Класс ПО (по классификатору Минцифры):** Прикладное программное обеспечение / средства автоматизированного проектирования (САПР) / отраслевое инженерное ПО для горнодобывающей промышленности.

**Назначение.** «ПВ-Система» — профессиональный программный комплекс для проектирования, моделирования и инженерного расчёта систем вентиляции и противопожарного водоснабжения подземных горных выработок (шахт, рудников). Программа предназначена для построения компьютерной модели шахтной вентиляционной сети, расчёта воздухораспределения, оценки аварийных вентиляционных режимов при пожарах и взрывах, гидравлического расчёта пожарно-оросительного водоснабжения, а также подготовки материалов для планов ликвидации аварий (ПЛА).

**Область применения:**
- проектные и научно-исследовательские организации горного профиля;
- службы аэрологической безопасности и вентиляции горнодобывающих предприятий;
- военизированные горноспасательные части (ВГСЧ);
- разработка и актуализация планов ликвидации аварий (ПЛА);
- воздушно-депрессионные съёмки (ВДС) и адаптация компьютерных моделей вентиляционных сетей.

**Целевые пользователи:** горные инженеры, проектировщики систем вентиляции шахт и рудников, специалисты по промышленной и аэрологической безопасности.

## 2. ФУНКЦИОНАЛЬНЫЕ ВОЗМОЖНОСТИ

Программа реализует следующие функциональные модули:

### 2.1. Построение топологии вентиляционной сети
Создание графовой модели сети горных выработок из узлов и ветвей с трёхмерными координатами (X, Y, Z), привязкой к горизонтам, заданием геометрии выработок (круглая, прямоугольная, трапецеидальная, арочная, произвольная форма сечения), типов и параметров крепи.

### 2.2. Расчёт воздухораспределения
Расчёт распределения воздушных потоков в сети методом контурных расходов (метод Хэрди-Кросса) на основе законов Кирхгофа: баланс расходов в узлах и баланс депрессий в контурах. Итерационное решение системы нелинейных уравнений с контролем сходимости по давлению и расходу.

### 2.3. Расчёт аэродинамического сопротивления
Вычисление аэродинамического сопротивления выработок по формуле Аткинсона (Жирара-Добюссона) R = α·L·P/S³ и трубопроводов R = 6.48·α·L/D⁵. Поддержка справочников коэффициентов аэродинамического сопротивления по типам крепи и поверхностей, учёт местных сопротивлений.

### 2.4. Каталог вентиляторов и подбор рабочей точки
Справочник вентиляторов главного (ГВУ), вспомогательного (ВВУ) и местного (ВМП) проветривания с напорными характеристиками H(Q). Определение рабочей точки как пересечения характеристики вентилятора с характеристикой сети, расчёт КПД и потребляемой мощности, учёт угла установки лопаток, оборотов, реверса и параллельной работы вентиляторов.

### 2.5. Расчёт аварийных режимов при пожаре
Моделирование очага подземного пожара, расчёт тепловой депрессии, оценка устойчивости проветривания наклонных и вертикальных выработок (в том числе опрокидывания вентиляционной струи), расчёт распространения продуктов горения (CO, CO₂, дым) по сети. Справочник горючих материалов.

### 2.6. Расчёт взрывных режимов
Оценка параметров ударной воздушной волны при взрыве горючих газов и взрывчатых веществ (методики на основе формулы Садовского и нормативных документов), расчёт зон поражения по избыточному давлению.

### 2.7. Гидравлический расчёт противопожарного водоснабжения
Расчёт водопроводной сети (трубопроводы, насосы, регуляторы давления, потребители — пожарные стволы, распылители, пеногенераторы) по формуле Дарси-Вейсбаха, определение расходов, давлений и времени работы.

### 2.8. Расчёт маршрутов горноспасателей (ПЛА)
Поиск оптимальных маршрутов передвижения отделений ВГСЧ по алгоритму Дейкстры с учётом нормативных скоростей хода, углов наклона выработок, задымления и расхода кислорода дыхательных аппаратов.

### 2.9. Визуализация и оформление
Двумерное и трёхмерное отображение вентиляционной схемы, цветовые палитры по расходу/скорости/давлению/горизонтам, условные обозначения, индикаторы параметров на ветвях, масштабирование и панорамирование.

### 2.10. Импорт и экспорт данных
Экспорт результатов в форматы Microsoft Excel (.xlsx), CSV, PDF, SVG, RTF/DOCX. Импорт данных из Excel, CSV, DXF и сторонних систем моделирования вентиляции. Хранение проекта в собственном формате (JSON-структура).

### 2.11. Лицензирование и администрирование
Онлайн-система лицензирования с привязкой к рабочему месту, поддержка автономного (офлайн) ключа на основе криптографической подписи, административная панель управления лицензиями.

## 3. АРХИТЕКТУРА ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

Программа построена по клиент-серверной архитектуре и состоит из следующих компонентов:

### 3.1. Клиентская часть (фронтенд)
Одностраничное веб-приложение (SPA), выполняющееся в браузере пользователя. Реализует пользовательский интерфейс, редактор схемы, визуализацию и значительную часть инженерных расчётов на стороне клиента.

### 3.2. Серверная часть (бэкенд)
Набор бессерверных облачных функций (cloud functions) на языке Python, выполняющих ресурсоёмкие вычисления, генерацию документов, проверку лицензий и служебные операции. Взаимодействие клиента с сервером осуществляется по протоколу HTTPS (REST, обмен данными в формате JSON).

Состав серверных функций:
- `airflow` — расчёт воздухораспределения в сети;
- `aerodynamics` — расчёт аэродинамического сопротивления;
- `water-hydraulics` — гидравлический расчёт водоснабжения;
- `rescue-calculator` — расчёт маршрутов горноспасателей;
- `explosion-calculator` — расчёт параметров взрыва;
- `svg-to-pdf` — формирование PDF-документов из схемы;
- `license`, `admin-licenses` — проверка и администрирование лицензий;
- `app-version`, `compute-config` — служебные функции (версия, конфигурация);
- вспомогательные функции подготовки графических ресурсов.

### 3.3. База данных
Система управления базами данных **PostgreSQL** (свободное ПО с открытым исходным кодом). Используется для хранения данных лицензий и служебной информации.

### 3.4. Файловое хранилище
Объектное хранилище (S3-совместимое) на российской инфраструктуре для хранения графических ресурсов и сформированных документов.

## 5. СИСТЕМНЫЕ ТРЕБОВАНИЯ

### 5.1. Веб-версия (клиент)
- Современный веб-браузер (Яндекс.Браузер, Chromium-совместимые браузеры) актуальной версии;
- процессор: 2 ядра и выше;
- оперативная память: не менее 4 ГБ (рекомендуется 8 ГБ для крупных схем);
- разрешение экрана: от 1366×768;
- подключение к сети Интернет (для серверных расчётов, лицензирования и обновлений).

### 5.2. Настольная (desktop) версия
- Операционная система: Windows 10/11 (64-бит); поддерживается запуск в среде совместимых российских операционных систем на базе Linux;
- процессор: 2 ядра и выше;
- оперативная память: не менее 4 ГБ;
- свободное дисковое пространство: не менее 500 МБ.

### 5.3. Серверная часть
- Среда исполнения Python 3.11;
- СУБД PostgreSQL 14 и выше;
- S3-совместимое объектное хранилище.

## 6. РУКОВОДСТВО ПО УСТАНОВКЕ И ЗАПУСКУ

### 6.1. Веб-версия
Веб-версия не требует установки на компьютер пользователя. Для начала работы необходимо:
1. открыть веб-браузер;
2. перейти по адресу размещения приложения;
3. авторизоваться (при необходимости) и активировать лицензию.

### 6.2. Настольная версия
1. Скачать установочный файл (дистрибутив) для соответствующей операционной системы.
2. Запустить установщик и следовать инструкциям мастера установки.
3. При первом запуске активировать лицензию (онлайн-активация или ввод автономного ключа).
4. Обновления устанавливаются встроенным механизмом обновления по уведомлению.

### 6.3. Развёртывание серверной части (для правообладателя / администратора)
1. Установить среду Python 3.11 и зависимости серверных функций (файлы `requirements.txt` в каталогах функций).
2. Развернуть и инициализировать базу данных PostgreSQL, применить миграции из каталога `db_migrations`.
3. Настроить параметры подключения к БД и хранилищу через переменные окружения (секреты).
4. Развернуть облачные функции и получить их адреса (URL).
5. Собрать клиентское приложение командой сборки и разместить статические файлы на веб-сервере.

Команды сборки клиентской части:
```
npm install      # установка зависимостей
npm run build    # сборка производственной версии
```
Результат сборки (каталог `dist`) размещается на веб-сервере.

## 7. ПОРЯДОК ЭКСПЛУАТАЦИИ (КРАТКО)

1. Создать новый проект или открыть существующий.
2. Построить топологию вентиляционной сети (узлы и ветви) вручную или импортом из внешних данных.

5. Проанализировать результаты (расходы, скорости, депрессии), выполнить при необходимости расчёты аварийных режимов (пожар, взрыв), гидравлики водоснабжения, маршрутов ВГСЧ.
6. Оформить и экспортировать результаты в требуемые форматы (Excel, PDF, SVG).
